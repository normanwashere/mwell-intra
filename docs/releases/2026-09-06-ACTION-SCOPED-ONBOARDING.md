# Action-scoped onboarding

Status: implementation candidate; not a UAT deployment declaration.

## Shared experience

All eleven operating personas use one learning checklist model, including accounts with several scoped roles. The experience adapts to assigned requirements and audience; it is not eleven separate onboarding implementations. Vendor presentation remains isolated to vendor assignments and documents.

Authorized workspace navigation no longer redirects to onboarding because an unrelated orientation is pending. Existing session, role, record, and server authorization boundaries remain unchanged. Pages that themselves require an uncertified capability can still be unavailable; this release does not invent a read permission for them.

## Action recovery

Required policy, assessment, simulation, and orientation evidence continues to govern the relevant action. The recovery panel names the missing requirements, opens the assigned learning in a new tab with an exact return path, and offers an explicit access refresh. The original form remains open; the operator must review current transaction state before submitting.

Unavailable learning status must never grant permission. Training is not a substitute for DOA, segregation of duties, evidence requirements, account status, or current role assignment. Existing certifications and shared UAT tester accounts are not reset.

## Knowledge Base

Common task destinations use maintained mappings, not a guessed keyword match. Guidance without a verified destination must not open an unrelated workflow. Detailed policies remain available as reference, while task guidance takes priority.

## Vendor responsibilities

The vendor evidence-responsibility exercise is a learning activity. It does not upload evidence, sign an MNDA, record a legal declaration, submit a case, or award accreditation. Those actions remain in their actual workflows with their existing evidence and authorization checks. A vendor return link remains within the vendor portal and retains its originating record parameters.

## Server enforcement and rollout

The candidate includes targeted server guards for legacy Warehouse PO cancellation and vendor PO acknowledgement. Cancellation requires the existing Procurement cancellation grant and certified PO-authoring capability; acknowledgement requires the existing vendor accreditation-submission capability to be certified. Existing status, ownership, document-hash, and revision checks remain in place. The SQL candidate was tested locally, not applied to UAT.

Checklist rows do not infer equivalent credit from similar titles. Existing server-side title/simulation-based orientation sharing remains unchanged; this UI change does not redefine that policy. The new vendor evidence exercise has no matching published UAT requirement. It therefore needs a separately reviewed, versioned requirement/curriculum publication, not an in-place metadata edit to immutable published content. Until then it is local catalog content only. Deploy and verify the reviewed database changes with the app before declaring this evolution live.

## Acceptance

- Fresh internal and vendor users can open their authorized workspace without blanket orientation redirects.
- A combined-role account can use one checklist; the UI must not infer cross-audience or cross-version credit.
- Unqualified, unauthorized, revoked, or unavailable-state actions remain denied.
- Learning recovery preserves the originating record tab, return path, and explicit access recheck.
- Desktop and mobile role journeys have functional and visual evidence.
- Local simulation results are reported separately from live certification and deployment.
